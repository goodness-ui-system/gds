Overview · Get Started

Get started.

Goodness is a small, honest foundation for interfaces — a fixed set of tokens and components built on one blueprint. This page gets you from zero to your first Goodness screen.

Honest by default. Every value in Goodness is derived, documented, and named. Nothing is magic; you can trace any pixel back to a token and any token back to the construction sheet.

Install

Goodness ships as CSS custom properties plus a lightweight component layer. Add it via package manager or a single stylesheet link.

# npm
npm install @goodness/core

# or drop the stylesheet in your <head>
<link rel="stylesheet" href="https://cdn.goodness-ui.com/v1/goodness.css">

The token prefix

Every compiled token is namespaced --gds- so Goodness is safe to drop into a codebase you don’t control — no collisions with Bootstrap, Tailwind, or a client’s legacy CSS.

.button {
  background: var(--gds-color-primary);
  border-radius: var(--gds-radius-md);
  padding: var(--gds-space-2) var(--gds-space-4);
}

The prefix is configurable. In a codebase you fully own, set it to empty for bare --color-primary — but keep --gds- anywhere Goodness is embedded in a host you don’t control.

// goodness.config
{ prefix: "gds-" }   // default · safe everywhere
{ prefix: "" }       // bare · only in fully-owned code

Whichever you pick, the authoring API stays bare: you write color.primary, and the prefix only appears in compiled output.

Principles

PrincipleWhat it means
HonestEvery value is derived and named — no untraceable magic numbers.
ConstructedThe identity and the geometry come from one blueprint (R62, 8-node G).
PortablePrefixed tokens drop into any codebase without collisions.
Monochrome-firstThe brand rests on one ink per ground; color is a supporting system, used with intent.
